# 版本说明（面向用户）

> 每个版本一段，写清**「这一版对你有什么变化」**。GitHub Release 的正文就取自这里。
> 最新版本在最上面。
>
> **版本号只有一个真源**：GitHub Releases 页上那个版本的 **tag**。
> 这个仓库没有 `package.json`、没有 `gradle.properties`，任何文档里写的版本号都只是
> tag 的副本——对不上时一律以 Releases 页为准。本文件最新的那个版本号必须与最新 tag 对应。
>
> 当前对齐状态：Releases 页上最新的 tag 是 `v0.1.0`（对应 `0.1.0-SNAPSHOT`）。
> 本文件最上面的 `0.1.1-SNAPSHOT` 是**待发布**的一节 —— 发布这一版时必须同时打
> tag `v0.1.1`，否则这里就又成了第二个版本号来源。
>
> 写法：**一个 `##` 一个版本 → 一句话摘要 → 分类小节 → 升级须知**。
> 分类标题一律用 Keep a Changelog 的英文原名：`Added` / `Changed` / `Deprecated` /
> `Removed` / `Fixed` / `Security`，加两个补充：`Known limitations` / `Upgrade notes`。
> 硬规则：同一版本 `Fixed` 只出现一次（多件事用列表分条）；标题里不放括号和技术名词；
> 写"用户感受到什么"而不是"改了哪行"；没解决的事写进 `Known limitations`，不要藏着；
> `Upgrade notes` 里只写"装之前要知道的"，测试步骤和单测数字属于技术细节，放进对应条目内部。
>
> **历史段落里的数字不跟着改**：`0.1.0-SNAPSHOT` 一节写的是**那个 tag 上**的实测值
> （498 条断言），`0.1.1-SNAPSHOT` 一节是 575 条。把它们统一成最新数字，会让历史版本
> 的说明与它对应的代码对不上，那比"看起来过时"更糟。

## 0.1.1-SNAPSHOT

> **别人不会再顺手读走你的验证码，库也不会再被"开两次"写坏。** 这一版修的是安全和
> 数据完整性，手上还有 0.1.0 的请换掉。

### Added

- **验证码历史从"存了但看不见"变成能用。** 此前扫描结果确实加密写进了
  `data/history.enc`，可页面上一个入口都没有——除了直接调接口，你没法看、没法标已用、
  没法导出，等于这个功能不存在。现在有独立视图：按账户或关键词检索、按时间范围筛选、
  只看未用的、单条与批量标记已用、导出为文本或 CSV、按时间范围清理。清理是两步确认
  （先选范围，再确认），不会一键抹掉全部。

### Fixed

- **双击两次不会再写坏密钥库。** 之前第二个实例会顺延到下一个端口照样启动，两个进程
  共用同一个临时文件写 `vault.enc`，交替写入几轮后整库变成解析不了的字节。现在第二个
  实例直接拒绝启动，并告诉你是哪个进程、锁文件在哪。进程异常退出留下的陈旧锁会被自动
  接手（记录里的进程已经不在了就接管），不需要你手工删。

- **忘了口令的人，用恢复密钥进来之后能设新口令了。** 此前这条路是死胡同：恢复解锁成功，
  但"改口令"仍然要求输入原口令——你正是因为忘了原口令才用恢复密钥的，于是被锁在门外。
  现在恢复解锁的会话可以直接设新口令；改完恢复密钥仍然有效（逃生门不能丢），旧口令同时
  失效。新口令的强度校验一步没放松，锁定的库也仍然不能被改口令。

- **密钥体检不再把好钥匙报成坏钥匙。** `tools/check-key.js` 之前不认 v2 库的 AAD，
  拿正确的密钥也报认证失败、退出码 1。这个工具唯一的用途就是判断哪把钥匙能开库，
  误报会直接把人引去删掉正确的那份。现在它按库自己的版本判定，并且把「钥匙不对」和
  「库里有坏条目」分开报——前者提示换钥匙，后者提示别动钥匙。

- **几百个账号的批量收码不会再中途被砍断。** 硬时限原来写死 15 分钟，而 300 个账号在
  最坏情况下要 42 分钟，正常流程必然被截断：界面只多一行"已终止"，后面的账号根本没扫。
  现在硬限按队列长度、单账号超时和并发推导（300 个账号约 46 分钟），同时保留 10 分钟
  下限和 60 分钟上限——上限必须在，它是单例锁唯一的兜底释放路径。

- **出错时能看到真正的原因。** 服务端一直把两类信息一起放进响应：细节（例如"单账号
  扫描超时（25 秒），已断开连接"）和归类（例如"网络超时或连接被重置"），但前端只显示
  前者、把归类丢掉了。于是 500 类错误你只看到"服务器内部错误，详见终端日志"，而答案
  就在响应里。现在归类会跟在细节后面显示，且不改写原有文案——批量收码轮询按文案做过判断。

### Security

- **别的程序不会再顺手拿到你的验证码了。** 这是本次最严重的一条。此前任何本机程序
  一个 `GET /api?action=handshake` 就能换到会话令牌，然后在你解锁期间读走全部 TOTP 明文、
  导出条目，甚至把空闲自动锁定改成 0 并持久化——"必须有主口令才能看秘密"这条边界，
  对同机进程是完全敞开的。现在握手要出示一个只存在数据目录里的 256 位本机秘密：浏览器
  第一次打开会让你粘贴一次授权码（终端启动横幅会打印它的绝对路径，通常是
  `KeyDesk/data/handshake`），校验通过后下发 HttpOnly cookie，一年有效；脚本改用
  `X-KeyDesk-Handshake` 头。引导只接受同源请求，连续粘错会短暂冷却。

  这条边界没有被说满：**与 KeyDesk 同一个系统账户下运行的代码仍能读到这个文件**，
  从而完全控制密钥库。那只能靠系统账户边界，应用层的鉴权堵不住。

- **别的 Windows 账户不会再读到你的账户库了。** MailDesk 的权限收紧原来只在启动时
  做一次，之后每次保存都会把一个继承态的新临时文件换上去，上一轮收紧的成果当场被覆盖
  回来（实测：建库后只有当前用户可读，再存一次就退回 SYSTEM / Administrators /
  Authenticated Users 可读）。也就是说，只要这一次运行期间保存过，磁盘上的
  `accounts.enc` 就一直对本机其他账户可读，直到下次重启才短暂收紧——而它旁边就是
  密钥文件，两样都能拿到，前面那道授权门等于白关。现在每次写盘都在替换**之前**收紧
  临时文件（NTFS 的替换带过去的是被移动文件自己的 ACL），验证码历史 `history.enc`
  同样处理，它此前从未被收紧过。

  回归断言：`MailDesk/selftest.js` 159 条、`MailDesk/security-test.js` 64 条、
  `MailDesk/tools/check-key-test.js` 27 条、`KeyDesk/selftest.js` 241 条、
  `KeyDesk/security-test.js` 84 条，合计 **575 条**，全绿。关键修复都钉成了断言；
  变异验证是开发期间手工做的，**仓库里没有可复跑的变异测试脚本**。

### Known limitations

- **KeyDesk：恢复密钥相当于一把完整的备用钥匙。** 它既能解锁，也能直接设新口令。
  这是"忘了口令不至于永久失锁"的代价。改完口令请顺手重新生成恢复密钥，否则旧的那串
  长期有效。
- **KeyDesk：改口令不换数据密钥。** 任何一份历史 `vault.enc` 副本 + 旧口令，仍然能解开
  **当前**数据。怀疑口令泄露时，改口令不等于止损，只能重建密钥库并重绑 2FA。
- **KeyDesk：用旧版 `vault.enc` 覆盖新版检测不到**——没有外部锚点，密文校验对"合法的
  旧密文"照样通过。
- **KeyDesk：加密导出包能生成，但工具里没有导入入口。** 目前只能自己写脚本解开，
  日常备份仍应拷 `vault.enc`。
- **KeyDesk：实例锁只认带锁的实例。** 锁文件是 `data/server.lock`，老版本不写它。
  升级后请先关掉旧版本再启动新版本，否则锁看不见那个进程。
- **MailDesk：批量扫描的硬限上限是 60 分钟。** 按并发 3、单账号 25 秒算，超过约 390 个
  账号仍可能撞上限——上限必须存在，但大任务会因此被截断。
- **MailDesk：`data/` 和 `~/.maildesk/vault.key` 必须成对备份**，缺一个另一个就没用，
  也不要把两者放进同一个同步盘。
- **MailDesk：只能管 Outlook / Microsoft 账号**，且需要你自己准备 `client_id` +
  `refresh_token`。工具里没有授权流程，README 也还没写怎么拿——这是已知的文档缺口。
- **两个工具都防不住**：内存 dump、键盘记录、录屏、恶意浏览器扩展，以及同一系统账户下
  运行的任意代码。Node 没有 mlock，加密在这些面前基本无效。

### Upgrade notes

- **不用重装**：这个项目不提供安装包。`git pull`（或重新 clone）后照原样
  `cd MailDesk && node server.js`。
- **数据格式没变**：0.1.0 的 `vault.enc` / `accounts.enc` / `history.enc` 直接可用，
  不需要迁移，也不需要重新导入。
- **KeyDesk 升级后第一次打开会让你粘贴一次本机授权码**：路径在终端启动横幅的
  `Auth file:` 那行（通常 `KeyDesk/data/handshake`）。浏览器记住一年，之后不再问。
- **KeyDesk 现在拒绝双开**：看到"检测到正在运行的实例"就先关掉那个窗口；确认它确实
  不在了，按提示删掉 `data/server.lock` 再启动。
- **之前跑过 `tools/check-key.js` 并被告知"钥匙打不开库"的，重跑一次**：那多半是误报，
  先把正确的那份留下来，别删。

## 0.1.0-SNAPSHOT

> **两个工具第一次公开。** 批量管邮箱、集中管 2FA，都是零依赖、纯本地，数据不出机器。

> **这一节是对原 Release 正文的重写**，改正了三处与代码不符的说法：
> ① 原文写 TOTP"密钥不进浏览器内存，连 XSS 和恶意扩展都拿不到"——实际"显示密钥"和
> "二维码"两条路径会把明文密钥放进浏览器内存；② 原文把"云盘历史版本"写成两个工具共同
> 的边界——实际只对 KeyDesk 成立（MailDesk 没有口令，密钥是独立文件）；③ 原文说测试里
> 包含可复跑的变异测试——实际没有，那是开发期间手工做的。另外，原文把验证码历史列进
> 了可用功能，但这一版的页面上没有它的入口（见下面的已知限制）。

### Added

**MailDesk**

- **批量导入** —— 按内容识别列（`client_id` 是 GUID 形状、`refresh_token` 最长），
  不按位置；四列/三列混排的导出文件都能读
- **可用性检测** —— 单个或批量，区分「令牌失效」和「账号被封」，后者不重试
- **收信 / 发信** —— IMAP 收件箱（含垃圾箱、已发送），SMTP 发纯文本
- **批量收验证码** —— 多选账户一次扫完，进度条 + 可取消，结果按账户分组
- **平台标注** —— 标出每个邮箱注册过哪些服务（内置 17 个 + 任意自定义名），按平台筛选、
  批量配置、导出 CSV 清单

**KeyDesk**

- **TOTP** —— 列表和详情页的 6 位码由服务端计算，页面只拿到数字。⚠️ 但点「显示密钥」
  或「二维码」时明文密钥会进入浏览器内存（拼 otpauth URI 必需），那两条路径的边界只有
  CSP 和同源策略
- **恢复码** —— 代际管理（哪一批是哪次生成的），逐码标记已用并显示日期
- **双槽解锁** —— 口令 或 恢复密钥，忘口令不会永久失锁
- **强制回填** —— 首次设置后必须回填恢复密钥的第 2/5/7 段才能进入，抄错进不去
- **加密导出** —— 独立盐和 IV，域分离 AAD，导出包不能当主库用
- **审计视图** —— 一眼看出哪些账号缺 2FA、缺恢复码、恢复码过期

**共同**

- **零第三方依赖** —— 没有 `package.json`，没有 `node_modules`；QR 编码（含
  Reed-Solomon）与 TOTP 均为自实现
- **安全设计写在文档里** —— KeyDesk 有一张「能防什么、防不住什么」的逐条对照表；
  MailDesk 写了本机鉴权模型、密钥与密文分离的理由、一轮红队审计的结果，以及已知缺陷。
  两者都不夸大，但**格式不统一**：MailDesk 没有 KeyDesk 那样的一张表。

**这一版的测试是四套共 498 条**（`MailDesk/selftest.js` 146、`MailDesk/security-test.js` 55、
`KeyDesk/selftest.js` 226、`KeyDesk/security-test.js` 71），全部通过。这是**这个 tag 上**
的数字；修复之后是五套共 575 条（多出 `MailDesk/tools/check-key-test.js` 的 27 条），
见上一节。原文还写"其中包含变异测试：把每个安全修复逐条改回 bug 版本，确认对应断言会
变红"——**这句不成立**，仓库里没有可复跑的变异测试脚本，那是开发期间手工做过的事。

### Known limitations

- **这一版的 KeyDesk 有三个已确认缺陷，0.1.1 已修**：握手无条件发令牌（同机任意进程
  可读明文 TOTP）、没有实例锁（双开会写坏 `vault.enc`）、恢复密钥解锁后无法改口令
  （用户被锁在门外）。
- **这一版的 MailDesk 有五个已确认缺陷，0.1.1 已修**：验证码历史只有后端、页面无入口；
  `accounts.enc` 与 `history.enc` 在第一次保存后 ACL 退回继承态；批量扫描硬限写死
  15 分钟（300 个账号必被误杀）；`tools/check-key.js` 不认 v2 库，正确密钥也报解不开；
  出错时归类信息算完就被前端丢掉，只剩一句"服务器内部错误"。
- **云盘历史版本（只对 KeyDesk 成立）**：把 `vault.enc` 放在网盘里，改口令会清掉本地
  备份，但云盘保留的旧版本仍可用旧口令解开，必须手动删历史版本。
  **MailDesk 不存在这条。** 它的密钥是独立文件 `~/.maildesk/vault.key`，本来就不该和
  `data/accounts.enc` 一起放网盘——两者同时泄露等于全部账号失守。它也没有口令可改。
- **回滚攻击（KeyDesk）**：用旧版 `vault.enc` 覆盖新版检测不到，需要外部锚点。
- **弱口令（KeyDesk）**：常见模式已拦，但 `Tr0ub4dor&3` 这类"看着复杂实际有模式"的
  评估不了——熵来自长度，不来自复杂度。
- **MailDesk 没有授权流程**：只接受 `client_id` + `refresh_token`，只支持
  Outlook / Microsoft，README 里也没写怎么拿 token。
- **内存 dump / 键盘记录 / 录屏**：两个工具都防不住，Node 没有 mlock。

### Upgrade notes

- **这一版是 SNAPSHOT**：接口与数据格式在 0.1.x 期间仍可能变动，不建议放不可替代的数据。
- **没有预编译包**：需要 Node.js 18+，clone 后 `cd MailDesk && node server.js`
  （KeyDesk 同理）。
- **KeyDesk 的 `vault.enc` 与恢复密钥绝不能放在一起**，这是整套设计的核心纪律。
